# Study Vault — Libreria materiali + AI riassunti — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Nuova zona "Vault" dello Studio: l'utente carica PDF/file (blob in IndexedDB, già esistente) o incolla link YouTube; un AI locale (Ollama, già integrata per il Coach) analizza il materiale e produce riassunti ben fatti per studiare, salvati e riutilizzabili.

**Architecture:** 
- **File/PDF:** riusare il file-store esistente (`src/lib/file-store.ts`, IndexedDB 'ascend-files'). Estrazione testo PDF lato client con `pdfjs-dist` (canvas-free, solo text layer). 
- **YouTube:** link → endpoint Ollama non può fare scraping; si usa la **descrizione + metadati** via `https://www.youtube.com/oembed?url=...&format=json` (nessuna API key, CORS ok) per titolo/autore; il riassunto AI si basa sul titolo/descrizione/trascrizione manuale incollabile dall'utente (campo opzionale "trascrizione/descrizione"). NOTA onesta: senza server non si può scaricare la trascrizione YouTube dal browser (CORS), quindi MVP = AI riassume su titolo+descrizione+note utente, con campo "trascrizione" incollabile (utente la copia dal pulsante "Mostra trascrizione" di YouTube).
- **AI:** `coachChat` di `src/lib/ai.ts` (Ollama localhost:11434, già usata dal Coach) con prompt dedicato per riassunti strutturati in markdown.
- **Persistenza:** nuova collezione `studyMaterials` + migrazione DB v10→v11 (stessa semantica di knowledgeMaps). I blob restano in IndexedDB (metadati nel DB: nome, tipo, size, mime).

**Tech Stack:** Next.js client components, `pdfjs-dist` (extract text client-side), Ollama via `coachChat`, storage esistente, `@xyflow/react` già presente.

## Task 2 — Estrazione testo (PDF + helper YouTube)

**Files:**
- Create: `src/lib/materials.ts`

**Contenuto:**
1. `extractPdfText(file: File): Promise<string>` — dinamico `const pdfjs = await import("pdfjs-dist")`, `pdfjs.GlobalWorkerOptions.workerSrc = new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url).toString()` (pattern worker v4 raccomandato; verificare la versione installata in node_modules e adattare il path del worker). Loop su `pdf.numPages` (max 60 pagine, YAGNI), `getTextContent()` → join items.str con spazi, pagine separate da `\n\n`. Limitare output a ~60k caratteri (taglia coda con "…[troncato]").
2. `youtubeId(url: string): string | null` — regex su watch?v=, youtu.be/, shorts/.
3. `fetchYoutubeMeta(url): Promise<{ title: string; author: string } | null>` — fetch `https://www.youtube.com/oembed?...&format=json`, catch → null (mai bloccare).
4. `chunkForPrompt(text: string, max = 24000): string[]` — spezza per paragrafi per prompt multipli (chunking semplice: se testo > max, split su doppio newline raggruppando).
5. `buildSummaryPrompt(title, text, kind): ChatMsg[]` — system prompt italiano: sei un assistente di studio per un universitario di informatica; produci un riassunto STRUTTURATO in markdown con sezioni fisse: "## In sintesi" (3-5 frasi), "## Concetti chiave" (bullet con definizioni), "## Approfondimenti" (punti meno ovvi), "## Domande da ripasso" (5 domande con risposte brevi), "## Glossario" (tabella termine/significato). Regola: usa SOLO il testo fornito, non inventare.
6. `summarizeMaterial(material, model): Promise<string>` — compone prompt, chiama `coachChat` (da `@/lib/ai.ts`), ritorna markdown. Se chunk>1: riassunto incrementale (riassume chunk1 → "PARZIALE1", poi riassume PARZIALE1+chunk2, ecc.) per non sforare la context window.

**Install:** `npm install pdfjs-dist` (versione 4.x; verificare API import ESM).

**Verifica:** typecheck + piccolo test manuale console (extract su un PDF reale). Commit: `feat(study): estrazione testo PDF + helper YouTube + prompt riassunti`.

## Rischi / Note

1. **pdfjs-dist** è la dipendenza più delicata: worker v4 con `new URL(..., import.meta.url)` funziona con Turbopack/Next 15+, testare in dev e build. Fallback se worker fallisce: `pdfjs.GlobalWorkerOptions.workerSrc` con CDN non accettabile (privacy) → usare `pdfjs-dist/legacy/build/pdf` se serve.
2. **YouTube**: impossibile scaricare trascrizioni dal browser (CORS) — MVP onesto: oembed per metadati + campo trascrizione incollabile dall'utente; l'AI riassume quel testo. Documentarlo nell'UI ("copia la trascrizione da YouTube: … » Mostra trascrizione").
3. **Context window Ollama**: chunking + riassunto incrementale già pianificato (chunkForPrompt/summarizeMaterial).
4. **Privacy**: tutto locale, nessun dato esce (Ollama localhost). Documento coerente col Coach.
5. **Dimensione PDF**: cap 60 pagine/60k caratteri per prompt; PDF scansionati (immagini) NON funzionano senza OCR — messaggio chiaro se il testo estratto è quasi vuoto: "PDF probabilmente scansionato: serve OCR (non supportato in MVP)".
6. **v2:** flashcard generate dai riassunti, quiz, integrazione mappe (nodo → materiale), ricerca full-text nel vault.
