# Obiettivi Personalizzati con Reminder in Home — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Obiettivi PERSONALIZZATI liberi (testo + valore numerico + periodo), separati dai DailyGoal automatici esistenti, con check manuale giornaliero e card Reminder in Home che li mostra fino a completamento/spunta.

**Architecture:** Nuova collezione `customGoals` (DB v12). Ogni goal: titolo libera (es. "Fare 20 esercizi SQL", "Ripassare algoritmi prima dell'esame"), opzionalmente target numerico + unità, frequenza (giornaliero / specifici giorni della settimana / solo fino a scadenza), soft-deadline. Il check è MANUALE (spunta): l'utente conferma di averlo fatto oggi — diverso dai DailyGoal che sono calcolati automaticamente dalle attività. La Home mostra la card "Obiettivi personalizzati" con gli obiettivi dovuti OGGI, spuntabile al volo; lo storico dei check permette contatore streak e % completamento.

**Tech Stack:** Tipi + migrate v12 (stesso schema delle precedenti), UI React esistente (Card/Modal/Button/Icon), card Home nuova seguendo MissingTodayCard come riferimento.

## Task 1 — Tipi + migrazione DB v12 + sync

**Files:** `src/lib/types.ts`, `src/lib/storage.ts`, `src/lib/db.ts`, `scripts/sync-server.mjs`

**Tipi:**
```ts
/** Obiettivo personalizzato (check manuale, non calcolato) */
export interface CustomGoal {
  id: string;
  title: string;              // es. "Ripassare algoritmi"
  note?: string;              // dettaglio opzionale
  target?: number | null;     // quantità opzionale (es. 20 esercizi)
  unit?: string;              // es. "esercizi", "pagine", "minuti"
  frequency: "daily" | "weekdays" | "weekly"; // weekdays = lun-ven; weekly = una volta a settimana
  weekDays?: number[];        // con frequency weekly: giorni (0=dom...6=sab) in cui è dovuto
  dueDate?: string | null;    // soft-deadline "yyyy-MM-dd" (dopo, scompare dai reminder ma resta in lista)
  color?: string;             // hex opzionale per il badge in home
  active: boolean;
  createdAt: string;
  updatedAt: string;
}

/** Check manuale di un giorno per un CustomGoal */
export interface CustomGoalCheck {
  id: string;
  goalId: string;
  date: string; // "yyyy-MM-dd" — un solo check per goal+giorno (upsert)
  createdAt: string;
}
```
DB: `customGoals: CustomGoal[]; customGoalChecks: CustomGoalCheck[];` — DB_VERSION 12 — migrate — dedupe — LIST_KEYS — seedDB.

**Verifica:** typecheck. Commit: `feat(db): customGoals + customGoalChecks (v12) + sync`.

## Task 2 — Logica compute

**Files:** Create `src/lib/custom-goals.ts`

**Funzioni pure (stesso stile di compute.ts):**
1. `isDueOn(goal: CustomGoal, dayKey: string): boolean` — daily sempre; weekdays → lun-ven (getDay 1-5); weekly → weekDays.includes(getDay); + active + (dueDate assente o dayKey <= dueDate).
2. `checkedOn(checks: CustomGoalCheck[], goalId: string, dayKey: string): boolean` — find goalId+date.
3. `dueToday(db: DB): CustomGoal[]` — isDueOn(today) per ogni active.
4. `streakOf(checks, goalId, todayKey): number` — conta giorni consecutivi checked partendo da oggi (o ieri se oggi non ancora fatto — stesso pattern activityStreak), rispettando isDueOn (i giorni in cui non era dovuto non rompono lo streak).
5. `completionRate(checks, goal, days=30): number` — % giorni dovuti con check negli ultimi 30.

**Verifica:** typecheck + mini test node (funzioni pure). Commit: `feat(goals): logica custom-goals (due/streak/completion)`.
